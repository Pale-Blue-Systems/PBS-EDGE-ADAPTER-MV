# Appendix A — PBS to BPv7 Mapping Specification  
**Document ID:** PBS-BPv7-MAPPING-APPENDIX  
**Status:** Reference Draft  
**Applies To:** PBS-EDGE-ADAPTER-MV  

---

## A.1 Purpose

This appendix defines the **deterministic mapping** between **Pale Blue Systems (PBS) envelopes** and **Bundle Protocol Version 7 (BPv7)** bundles as implemented by the PBS Edge Adapter Minimum Viable reference.

The mapping described herein enables PBS envelopes to be encapsulated into BPv7 bundles and reconstructed without loss of payload integrity or routing identity.

---

## A.2 Mapping Principles

The mapping adheres to the following principles:

1. **Determinism**  
   Identical PBS inputs and configuration produce identical BPv7 outputs.

2. **Opacity of Payload**  
   PBS payload bytes are treated as opaque and are not interpreted or modified.

3. **Authority Awareness**  
   All endpoint construction is scoped by the active Authority Context.

4. **Minimalism**  
   Only BPv7 elements required for correct delivery are populated.

---

## A.3 PBS Envelope Elements

For the purposes of this appendix, a PBS envelope is assumed to contain the following logical elements:

- PBS Version
- Source Identifier
- Destination Identifier
- Scope Identifier
- Message Identifier
- Payload (byte sequence)

Field naming is logical rather than implementation-specific.

---

## A.4 BPv7 Bundle Elements Used

The minimum viable mapping uses the following BPv7 elements:

- Primary Block
  - Destination Endpoint ID (EID)
  - Source Endpoint ID (EID)
  - Creation Timestamp
  - Lifetime
- Payload Block

No extension blocks are required.

---

## A.5 Endpoint Identifier (EID) Construction

### A.5.1 EID Scheme

The mapping assumes use of a BPv7-compliant EID scheme (e.g., `dtn` or `ipn`), selected by configuration.

The choice of scheme does not alter PBS semantics.

---

### A.5.2 Destination EID Mapping

The BPv7 **Destination EID** is derived as follows:

| Input Element        | Source            | Usage in EID Construction |
|----------------------|-------------------|---------------------------|
| Authority Context    | Adapter config    | Namespace root            |
| PBS Destination ID   | PBS envelope      | Node or service component |
| PBS Scope Identifier | PBS envelope      | Hierarchical qualifier    |

The resulting Destination EID uniquely identifies the target within the Authority Context.

---

### A.5.3 Source EID Mapping

The BPv7 **Source EID** is constructed using:

| Input Element        | Source            | Usage in EID Construction |
|----------------------|-------------------|---------------------------|
| Authority Context    | Adapter config    | Namespace root            |
| PBS Source ID        | PBS envelope      | Node or service component |

The Source EID represents the originating PBS entity within the same Authority Context.

---

## A.6 Primary Block Mapping

### A.6.1 Creation Timestamp

- The BPv7 Creation Timestamp is generated by the adapter at the time of bundle construction.
- The timestamp reflects adapter-local time.

---

### A.6.2 Lifetime

- The BPv7 Lifetime value is populated from adapter configuration defaults.
- Lifetime selection is independent of PBS payload contents.

---

## A.7 Payload Block Mapping

| PBS Element | BPv7 Element | Mapping Rule |
|------------|--------------|--------------|
| PBS Payload | Payload Block | Payload bytes are copied verbatim |

The adapter does not apply compression, encryption, fragmentation, or inspection to the payload in the minimum viable reference.

---

## A.8 Message Identity Preservation

The PBS Message Identifier is preserved logically through:

- Deterministic mapping to BPv7 endpoints
- Optional inclusion in local logging or diagnostics

No BPv7 extension block is required to preserve message identity in the minimum viable mapping.

---

## A.9 Reverse Mapping (BPv7 → PBS)

When reconstructing a PBS envelope from a received BPv7 bundle:

1. The Payload Block is extracted as the PBS payload.
2. Source and Destination EIDs are parsed.
3. PBS Source and Destination Identifiers are derived using:
   - The active Authority Context
   - Local EID parsing rules
4. A new PBS envelope is constructed and delivered to the local egress interface.

This process preserves routing identity and payload integrity.

---

## A.10 Error Handling

If a received BPv7 bundle cannot be mapped unambiguously to a PBS envelope under the active Authority Context, the adapter records the condition and does not emit a reconstructed envelope.

Error signaling behavior is implementation-defined but deterministic.

---

## A.11 Applicability and Extensibility

This appendix defines the **minimum viable** PBS ↔ BPv7 mapping.

Future extensions may introduce:

- Additional BPv7 extension blocks
- Enhanced identity binding
- Security-related encapsulation

Such extensions do not alter the correctness of the mapping defined herein.

---

## A.12 Summary

This mapping appendix establishes a clear, deterministic, and standards-aligned method for encapsulating PBS envelopes into BPv7 bundles and reconstructing them at the edge.

It is intended to support technical evaluation, interoperability testing, and standards review.
